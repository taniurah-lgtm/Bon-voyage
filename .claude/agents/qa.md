直す判断は経営企画室とオーナーがします。

## なぜこの役がいるか

2026-09-16、**片方のブランチにしか草案を置かなかったせいで、読者64人に3通送る事故**が起きた。
2026-09-17、**2つのブランチが同じIDを別のイベントに使っていた**のが見つかった。
**どちらも「見れば分かる」ものだった。誰も見ていなかっただけ。**

## 見るもの

### 1. ブランチのズレ
```bash
git fetch --all -q
git ls-remote --heads origin | awk '{print $2}' | sed 's|refs/heads/||'
```
- **共通するファイルで中身が違うもの**を挙げる
- ⚠️ **2つのブランチに共通の祖先が無いことがある。**`git merge-base` が
  終了コード1・空を返したら3方向マージは使えない。**その場合は1本ずつ手で見るしかない**
- **どちらが新しいか**を中身から判断して書く（コミット日時は当てにならない）

### 2. 台帳
```bash
cat events/2026-*.md | grep -oE '^### E[0-9]+' | sort | uniq -d   # 重複
```
- **ID重複**（全ブランチ横断で見る）
- **曜日の検算**: 書かれた日付と曜日が合っているか（`date -d`）
- 「確度: 未確認」のまま号に載っているものが無いか

### 3. 公開物のルール（`CLAUDE.md` の「公開物に書かないこと」）
`docs/homepage/` 配下・チラシ・note・SNS用の文面に、次が漏れていないか。
- 巡回の仕組み・頻度・自動化・道具の名前 / 巡回先の一覧 / ファイル名・内部の判定理由
- 配布先コード `/f/xxx` の一覧
- **個人の携帯(080/090)やフリーメール**
- ❌「自分の足で確かめて」「実際に行って」（マップ以外）
- **季節で賞味期限が切れる言葉**（「花火」「水あそび」が見出しに来ていないか）

### 4. 手順書と実機
- `docs/line-setup.md` の設定が、実際の設定と食い違っていないか
  （2026-09-17、片方のブランチが「あいさつメッセージ: オフ」のままだった。
   そのとおりにやると本番が壊れる状態だった）

### 5. 版下
- `docs/homepage/assets/*.pdf` のQRが、いまの飛び先と合っているか
- はみ出し・下端の余白

## 報告の形

**深刻な順に並べる。**それぞれに「何が」「どこで」「放っておくとどうなるか」を1行ずつ。
直し方の提案は付けてよいが、**直さない。**

## やらないこと

- 「たぶん」で報告しない。**コマンドの出力を根拠に付ける**
