# SNS自動投稿（Phase 0）

設計は `docs/social-automation.md`。ここは **Phase 0（生成のみ・投稿しない）** の実装。

## いま動くこと
- 毎日 07:00 JST（`.github/workflows/social-drafts.yml`）に `generate-drafts.mjs` が走り、
  `events/` の台帳から Gemini で **Threads/X のドラフト**を作って `social/drafts/YYYY-MM-DD.md` にコミットする。
- **投稿はまだしない**。生成物を人が見て確認する「承認ゲート」段階。

## 準備（オーナー）
1. `GEMINI_API_KEY` を発行（[Google AI Studio](https://aistudio.google.com/) / tokyo.papa.home）。
2. GitHub → **Settings → Secrets and variables → Actions → New repository secret** に
   `GEMINI_API_KEY` を登録。
3. （任意）モデル名を変えたいときは同じ画面の **Variables** に `GEMINI_MODEL`（例 `gemini-1.5-flash`）。
4. 手動テスト: Actions タブ →「SNS drafts」→ **Run workflow**。`social/drafts/` にファイルができる。

## いまの運用（手動コピペ）
Threads APIのトークン取得は保留中のため、当面は**手で貼る**運用:
1. 毎朝、最新の草案を開く（いつも同じURL）:
   `https://github.com/taniurah-lgtm/bon-voyage/blob/claude/family-event-planning-rfwmo8/social/drafts/latest.md`
   （GitHubにログインした状態で。前日ぶんは `social/drafts/YYYY-MM-DD.md`）
2. **【Threads・紹介】** をコピー → Threadsに貼って投稿。**毎日でよい。**
   飛び先 `bonvoya.nicomaru.tokyo/f` は入っている。
3. **【Threads・問いかけ】** は**隔日**（下書き自体が隔日でしか作られない）。
   紹介と同じ日に出すときは**半日〜1日ずらす。**
   🔴 **リンクもハッシュタグも足さない。**足すと宣伝に見えて、返事が来ない。
4. **返事が来たら、おでかけマップに入れる**（下記）。これが問いかけを出す本当の目的。

## ⭐ 問いかけ → おでかけマップ（2026-09-21）

**おでかけマップは、`CLAUDE.md` で唯一「実際に行ってよかった場所」と書いてよい場所。**
**地元の家庭の持ち寄りだから。**
**問いかけの返事は、その持ち寄りそのもの。**
→ **問いかけは、engagement のためではなく、マップの取材として回す。**

### 手順

1. 返事が付いたら、**お礼と「マップに足します」を返す。**
   **許可を求めるのではなく、見に来てもらう。**

   > 教えてくださってありがとうございます。
   >
   > いただいたお話を参考に、通信のホームページの「おでかけマップ」に足しておきます。
   > 地元の方に教えていただいた場所を集めている地図です。
   >
   > よければ覗いてみてください。
   > https://bonvoya.nicomaru.tokyo/map.html

   - ⭕️ **なぜ許可を求めないか**: **言葉は借りない。事実だけ使って、こちらの言葉で書く。**
     **事実に持ち主はいない。**「昼が空いている」は誰のものでもない
   - ⭕️ **そのうえで、足すことは伝える。**黙って使うのとは違う
   - ⭕️ **教えた人が、自分の話が載った地図を見に来る。**
     **地図の下にLINEの案内がある**（`scripts/build-map.mjs` の `.bvc-invite`）。
     **ここが Threads → マップ → LINE の導線**
   - 🔴 **例外: 言い回しごと載せたいとき**（そのままのほうが伝わる文だったとき）は、
     **そのときだけ「そのままの言葉で載せてもよいですか」と聞く。**
     **言葉を借りるなら、許可が要る**
2. `data/map-spots.json` の**そのスポット**に足す:

   ```json
   "fromReader": "お昼時が空いているため、早めor遅めにお昼ごはんを食べて遊ぶのがおすすめです。",
   "source": "読者のみなさんからのおすすめ（2026-09-02）"
   ```
   - **見本は「キッズランドUS mini 東京吉祥寺店」**（いま入っている1件）。
     ⚠️ **あれは本人の言葉がそのまま入っている。**
     **Threadsから足すぶんは、事実だけ取って、こちらの言葉で書く**
   - **スポットがまだ無ければ、新しく1件作る**（`cat` `name` `access` `desc` `ages` `map` `official`）
3. `node scripts/build-map.mjs` → commit & push
4. **足し終わってから、上の返信を送る。**
   🔴 **先に「足しておきます」と言って見に来てもらったら、まだ無い、では困る**

### 🔴 `facts` と混ぜない

| キー | 何を入れるか |
|---|---|
| `facts` | **公式で裏を取ったものだけ。**末尾に「（YYYY-MM-DD 公式で確認）」が付く |
| `fromReader` | **読者から聞いた話。**公式には書いていないこと（空いている時間帯・ベビーカーの実際・雰囲気） |

**混ぜると、どちらも信用を失う。**
**「公式で一件ずつ確かめています」と言えるのは `facts` を分けているから。**

### 名前は出さない

**アカウント名も本名も出さない。**`source` は「読者のみなさんからのおすすめ（日付）」で足りる。
（`CLAUDE.md`「個人の連絡先を機械可読で撒かない」と同じ考え方）

### 導線の全体

```
Threads の問いかけ
  → 返事（地元の人の実際の話）
    → おでかけマップに足す（事実だけ・こちらの言葉で）
      → 「足しました、見てください」と返す
        → 地図を見に来る
          → 地図の下の「LINEで受け取る（無料）」
```

- **教えた人が、いちばん見に来たくなる。**自分の話が載っているから
- **その人が見る画面の下に、LINEの案内がある**
- 🔴 **LINEの話を返信に書かない。**押しつけがましくなる。
  **`CLAUDE.md`「収益導線はホームページに預ける」と同じ。**地図に言わせる

## 🔴 なぜ「紹介」と「問いかけ」の2本なのか（2026-09-21）

**返信の付く投稿のほうが伸びる**、という観測から。
（オーナーが見つけた例: 淡々とした告知は いいね9、
　最後に「この現象知ってますか？？」と問いかけたものは いいね338・返信35）

- **紹介**: これまでどおり。イベント名・日付・場所・子連れ視点＋リンク＋タグ。**毎日**
- **問いかけ**: 同じ対象について、**読んだ人が答えたくなる問い**で終える。**隔日**
  - 🔴 **毎日聞くと「いつも聞いてくる人」になる**（2026-09-21・オーナー判断）。
    生成側で隔日にしてある（紀元からの通日の偶奇。月末月初でも2日続かない）。
    **今日ぶんを試したいときは `ASK_DAY=1` を付けて実行する**
- 🔴 **行ったことにしない。**「うちの子が」「先週行ったら」は**書かない。**
  **実際には行っていないので嘘になる**（`CLAUDE.md`「書いてよいこと・いけないこと」）
- ⭕️ **聞くのは「行く前に知りたいのに、公式に書いていないこと」。**
  混み具合・ベビーカー・駐車場・小さい子がどのくらい楽しめるか・近くのごはん
- ⭕️ **答えは、おでかけマップに書ける唯一の種類の情報**
  （マップだけは「実際に行ってよかった場所」と書ける。地元の家庭の持ち寄りだから）
