# 年齢別ページ（9/30号から）

**決定: 2026-09-27 オーナー。**当初は10/7号からの予定だったが、**9/30号から前倒し**（同日オーナー）。LINEは入口、中身はホームページの年齢別ページに置く。

## なぜ

| 困っていたこと | どう解くか |
|---|---|
| LINEは40行ほどが上限。ネタが多い週は選べない | 中身をページに移す。ページは何件でも、公式リンク・地図つきで載せられる |
| 西東京・東久留米に広げると、LINEがあふれる | 広げるときはページ（地域別）を足すだけ。LINEの行数は増えない |

| エリア別・年齢別の読者の関心が分からない | ページごとの閲覧数で見る（下の「数字の読み方」） |

## 数字の読み方（営業で言ってよいこと）

- GoatCounter の `/week/日付/baby/` などは **「ページが見られた回数」**。1人が2つ押せば2回。
  → 言ってよい: 「赤ちゃん向けのページが毎週○回見られている」 / 言わない: 「赤ちゃんのいる読者が○人」
- 各カードの「地図」ボタンは、押された回数を**イベント名ごと**に数えている（GoatCounter のイベント「地図｜イベント名」）。
  どの催しに行く気になったかの目安になる（協賛の営業で「お店の地図が○回開かれた」と言える）
- 🆕 **カレンダー登録ボタン（表示は「📅登録」。2026-10-04 オーナー指示・10/7号から）**も同じく「カレンダー｜イベント名」で数える。
  **地図より「行くつもり」に近い数字**。🔴 **2026-10-08 から「登録」を押すと、入れ先を選ぶ欄が開く**（iPhone の LINE の中で「押しても反応しない」と言われた）。
  - **iPhone（Mac）のカレンダー** … `/week/<日付>/cal/<番号>.ics`。**LINE の中では `?openExternalBrowser=1` を付けて Safari で開かせる**
    （LINE の中のブラウザは .ics を開けない）。Android・Windows には出さない
  - **Googleカレンダー** … 登録画面（これは LINE の中でも開く）
  - **TimeTreeなどに貼る（予定をコピー）** … TimeTree には外のサイトから予定を入れる入口が無い（外部連携の仕組みは 2023-12 に終了したと第三者の資料にある。公式の告知は未確認）。
    名前・日時・場所・公式URLをコピーして、アプリで貼ってもらう
  - 数え方は「カレンダー｜名前」（開いた数）に加えて「カレンダー(iPhone)｜」「カレンダー(Google)｜」「カレンダー(コピー)｜」
  時刻が分からないもの・複数日のものは終日。終わりの時刻が無いものは開始と同じ時刻にして、長さを推測しない。前日18:00に通知
- LINE公式アカウントの管理画面にも、**配信ごとのURLクリック数**が出る。両方を見る
  - 🆕 **2026-10-28号から、`node scripts/line-insight.mjs <配信日>` で、LINE を開いた人数・リンクを押した人数を直接取れる**（`docs/line-setup.md`「号の反応を LINE から見る」）

## 作り方（水曜巡回）

1. いつもどおり台帳を更新し、号に載せるものを決める
2. `reports/free/web/YYYY-MM-DD.json` を書く
   ```json
   {
     "date": "2026-10-07",
     "pick": "E105",
     "items": [ { "id": "E105", "note": "ひとこと（公開される）" }, { "id": "E153" } ],
     "ahead": [ { "id": "E111", "note": "申込は10/5まで" } ]
   }
   ```
   - `items` = 今週（週末・連休）、`ahead` = 先取り・締切
   - `note` を省くと、台帳の子連れメモが出る
   - **年齢で振り分けるのは台帳の目安（👶🧒🎒 の ◎○）。**ページに出ないときは台帳の目安を見直す
   - 🆕 **年齢別のひとこと（2026-11-04 オーナー「年齢別の内容はもっと差があるように」）**: 同じ催しでも、主な2〜3件は年齢ごとに書き分ける。
     `{ "id": "E187", "note": "共通（無い年齢に出る）", "notes": { "baby": "手形・足形アートは赤ちゃんの記念に…", "pre": "13:45のコダレンジャーに合わせて…", "elem": "射的とストラックアウト…" } }`
     - 👶 授乳・おむつ替え・ベビーカー・混む時間・寝んねの時間との兼ね合い／🧒 ショーや体験の時刻・遊具・お昼の段取り／🎒 体験・ゲーム・申込・自転車や電車での行き方
     - 書いていないことは「(要確認)」。台帳に無い事実は書かない
   - 🆕 **そのタブにしか出ない催しを、各タブ3件以上**（同じ日）。`build-weekly.mjs` が送る前の号について「そのタブにしか出ない催し: 👶…🧒…🎒…」を出す。⚠ が出たら `docs/sources.md`「年齢別のさがし先」から足す
     - ①（◎だけを上に）と④（◎の付け方を厳しく）は**やらない**（オーナー判断）。差は、年齢別のひとことと、その年齢向けの催しを足すことでつける
   - **並びは自動**（2026-10-25 オーナー）: 一推しがいちばん上、あとは**日付順**（同じ日は◎が先、始まる時間の早い順）。
     会期もの（〜11/8 など）は、週末の催しのあとに、終わりの日の早い順。**`items` の書き順は並びに関係しない**
3. LINE本文（`reports/free/YYYY-MM-DD.md`）を新しい形で書く（`CLAUDE.md`）
4. **06:55 準備Routine**（2026-10-10 に 07:50 から早めた。終わったらオーナーに「昨年の様子」のリンクを頼む）: 号と `web/<日付>.json`（`"ready": true`）を push → デプロイでページが出る → 3つのURLが200か確かめる
5. **09:00 配信Routine**: ページが開けるのを確かめてから LINE を送る → `sent.log` を push（ホームページのプレビューが切り替わる）

## 📷 インスタの「その時の様子」ボタン（2026-10-10〜）

オーナー発案: 文面と公式ページだけでは「行きたい」にならない。**実際の様子**を見せる。投稿主への「紹介しました」が、インスタの発信者とつながるきっかけにもなる。

- `reports/free/web/<日付>.json` の item に足す（2件まで）:
  ```json
  { "id": "E105", "note": "…", "insta": [ { "url": "https://www.instagram.com/p/xxxx/", "when": "2025-10", "by": "account_name" } ] }
  ```
- ボタンの文字は号の日付から自動で決まる: **「📷 3か月前の様子」「📷 昨年10月の様子」「📷 2024年10月の様子」**＋小さく「Instagram @…」。
  **1件1行の小さなピル**（2026-10-10 オーナー「余白を詰めて、縦に伸ばさない」）
  （🔴「雰囲気を見る」とは書かない。**いつの様子かをはっきり書く**＝今年と中身が違うことがある。オーナー指示）
- **写真は取り込まない。リンクだけ。**日時・料金は今までどおり公式から書く
- 🆕 **インスタ以外にも付けられる**（2026-10-10）: 主催の「開催しました」報告ページ、催しを訪ねた記事など。`"by"` にサイト名（例 `"津田塾大学"`）を書くと「津田塾大学のページ」と出る（YouTube の URL なら「ルネこだいらのYouTube」。2026-10-21 オーナー指示）。`when` は**投稿日ではなく、写っている催しの年月**
- URL・年月・アカウント名の形が違うと、ビルドが止まる（`instaProblems`）。`?igsh=…` などの後ろは自動で落とす
- 数え方: 「様子｜催しの名前」

### どの投稿を使うか（順番）

1. **主催者・会場の公式アカウント**（去年の様子でも可）→ 断らずに載せてよい。載せたあとに「紹介しました」
2. **お店・出演者・発信を仕事にしているアカウント**（インスタグラマー）→ 同じく断らずに載せて、あとで「紹介しました」
- 🔴 **議員・政党・選挙に出る人のアカウントは使わない**（2026-10-10）。通信は市の施設に置いてもらっている市民活動の紙なので、
  特定の議員の発信へ人を流すと、応援しているように見える。市民まつりの投稿が議員のものしか見つからなかったときに決めた
3. **ふつうの親子の個人アカウント** → 🔴 **先に一言ことわる**。返事が無ければ使わない。**よその子の顔が写っている投稿は使わない**
   （法律上はリンクだけなら許可は要らないが、130家庭に向けてその人の投稿へ人を集めることになる。本人が望んでいるとは限らない）

### 段取り

- 投稿を探すのは**オーナー**（インスタはログインしないと見られず、外から自動で探すのは規約で禁止。Claude には探せない）
- まずは**一推しの1件だけ**。URL・年月・アカウント名をチャットに貼れば Claude が入れて、「紹介しました」の文を作る

- 3〜4号続けて、押された回数で手間に見合うかを判断する
