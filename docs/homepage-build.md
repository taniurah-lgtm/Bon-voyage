# ホームページの組み立て方（カレンダー・地図・投稿）

`docs/homepage/` の中身は**手で書かない**。台帳とスポットのデータから組み立てる。
組み立て直すのは1コマンド。

```sh
MEMBER_PASS='実際の合言葉' MAP_POST_URL='https://script.google.com/macros/s/.../exec' \
  ./scripts/build-site.sh
```

`docs/homepage/**` を push すると `deploy-homepage.yml` が走って公開される。
**push 先は `claude/line-message-resend-yefv9l` のみ**（このブランチ以外ではデプロイが動かない）。

---

## 全体の流れ

```
events/*.md  ──build-events-json.mjs──▶  data/events.json      ← 全件・非公開
（台帳・rfwmo8が正）                            │
                                               ├──build-calendar.mjs──▶ docs/homepage/calendar.html
                                               │                        docs/homepage/data/events-public.json
                                               │                        ★公開される＝先2週間だけ
                                               │
                                               └──build-members.mjs──▶ docs/homepage/m/s7f2ka/index.html
                                                                        全件をAES-GCMの中に入れる

data/map-spots.json ──build-map.mjs──▶ docs/homepage/map.html
（座標は geocode-spots.mjs が入れる）           地図＋サイト内の投稿フォーム
data/map-posts.json ─────┘
```

描画のコード（`docs/homepage/assets/bv-*.js`）は公開されるが、**予定の中身は持っていない**。
会員限定の予定は暗号文の中にしか無いので、コードが読まれても先の予定は見えない。

## 1. 台帳を読む（`build-events-json.mjs`）

台帳の日時欄は人が書いた自由文なので、**取れなかったものを黙って落とさない**。
実行するたびに、載せられなかった件数と理由が必ず出る。

```
確定 32件 / 暫定 12件 / 常設・季節 5件 / 載せられなかったもの 14件
  - E32 ヒガコ・サマーフェスティバル: 日時から確定日が取れない 「例年8月上旬の2日間(2026年日程要確認)」
```

**この一覧は毎回目を通す。** 件数が急に増えていたら、台帳の書き方が変わったか、パーサが壊れている。

| 分類 | 何 | カレンダーでの扱い |
|---|---|---|
| 確定 | 日付が取れて、`例年`『要確認』を含まない | **マス目に置く** |
| 暫定 | 日付は取れたが `例年` `要確認` `見込み` を含む | マス目には置かず「日程がまだ確定していないもの」に出す |
| 会期 | `〜10/14(水)まで` や15日以上の区間 | 「会期中ずっと見られるもの」に出す |
| 常設・季節 | `- 期間:` があるもの、`〔常設〕` | 「いつでも行ける定番」に出す |
| 載せられない | 日時も期間も無い（「◯◯群」など）／終了・見送り | 出さない。理由がログに出る |

### 日時欄の読み方（気をつけるところ）

| 台帳の書き方 | どう読まれるか |
|---|---|
| `8/22(土)・23(日)` | 2日（`・`区切りは展開しない） |
| `8/18(火)〜23(日)` | **6日ぜんぶ**に展開する |
| `8/8(土)〜15(土)は毎日、ほか8/1・8/22` | 区間8日＋単発2日＝11日 |
| `〜10/14(水)まで` | 会期もの（開始日なし） |
| 16日以上の区間 | 会期もの（マス目が埋まって読めなくなるため展開しない） |
| `①9/29(火) ②10/13(火)` | 2日（選択制） |

**締切は「申込の行のいちばん後ろの日付」**として拾う。
`申込: 8/5(水)〜28(金)` は 8/28 が締切。
> ⚠️ ここは一度間違えた。区間が長いと `span` に落ちるため、当初は**開始日の8/5を締切と読んで**
> E48（締切8/28・台帳に「先取り情報として要掲載」と明記）を落としていた。
> パーサを直すときは、必ず台帳の記載と4件以上突き合わせる。

## 2. 座標（`geocode-spots.mjs`）

`data/map-spots.json` に `lat` / `lng` が無いものだけを OpenStreetMap の Nominatim で引く。
結果はJSONに保存して二度引かない（利用規約に沿って1秒1件に落としている）。

```sh
node scripts/geocode-spots.mjs          # 未取得のものだけ
node scripts/geocode-spots.mjs --all    # 全件引き直す
```

**取れなかったものに座標を書かない。** 推測で置くと地図が嘘をつく。
ピンが立たないだけで、一覧と「📍地図」（Google マップ検索）は変わらず使える。

| JSONの印 | 意味 |
|---|---|
| `geoQuery` | 施設名では引けないので、検索語を上書きしている |
| `geoSkip: true` | 1点に落ちない枠（「児童館・子育てひろば」など）。引かない |
| `geoApprox` + `geoNote` | ピンが施設そのものを指していない。ふきだしに「およその位置」と出る |

2026-08-23 時点: 23件のうち **ピン19件 / およその位置3件 / ピンなし4件**。
`花小金井ひょうたん池公園` は OSM に登録が無く（岩手・長崎の同名公園しか出ない）ピンなし。
地元の要なので、**OSM に登録されるか、別の手で座標が確認できたら入れる**。

## 3. 無料と有料の境目（ここを壊さない）

| | 公開（誰でも） | 会員ページ |
|---|---|---|
| カレンダー | **今日からの2週間** | **全件**（先の予定・締切・会期・常設ぜんぶ） |
| データの置き場 | `docs/homepage/data/events-public.json` | 暗号文の中（`m/s7f2ka/index.html`） |
| 地図 | 全スポット（薄くしない） | 同じ地図＋みんなの声が全件 |
| みんなの声 | 各スポット2件まで | 全件・写真つき |
| 投稿 | ひとこと40字まで | 300字＋写真1枚 |

**`events-public.json` に2週間ぶん以外が入っていないことを、公開前に必ず確認する。**

```sh
node -e 'const d=require("./docs/homepage/data/events-public.json");
console.log(d.window, d.events.flatMap(e=>e.dates||[]).sort().at(-1))'
```

> 公開側にカレンダーを足したのは**無料に足した分**で、削ったものではない。
> それまで公開側にカレンダーは1つも無かった。「無料を薄くして有料に誘導しない」方針は守っている。

## 4. 投稿の受け口（Google Apps Script）

Googleフォームには飛ばさない。`map.html` の中で書いて、そのまま送る。

置き方は `scripts/gas/map-post-endpoint.gs` の冒頭に書いてある。要点だけ:

1. Apps Script に貼って `setup` を実行 → スプレッドシートと写真の置き場ができる
2. 「デプロイ」→「ウェブアプリ」→ **アクセスできるユーザー = 全員**
3. 出てきたURLを GitHub の **Variables** に `MAP_POST_URL` として登録（Secretsではない。公開ページのJSに載る）
4. コードを直したら**必ず「新しいバージョン」でデプロイし直す**。保存だけでは公開中の中身は変わらない

**`MAP_POST_URL` が未設定でもフォームは出る。** 送信時に「まだ設定されていません」と出て、
書いた文章はコピーできる状態で残る（下書きは端末の localStorage にも残る）。**書いたものを捨てない。**

### 承認フロー（変えていない）

承認されるまで公開しない。スプレッドシートの `承認` 列に ✓ が入った行だけが `公開用` シートに出る。
そこから `data/map-posts.json` に取り込んでビルドし直すと地図に載る。

> ⚠️ **合言葉はスプレッドシートに残らない。** サイト側で判定した結果（一般／サポーター）だけが届く。
> 旧フォーム運用では合言葉が平文で残っていた。これは直った。

### 合言葉の判定の仕組み

`build-map.mjs` が `MEMBER_PASS` で「`ok`」という文字列だけを暗号化したブロブを埋める。
入力された合言葉で復号できれば `ok` が出る＝サポーターと判定する。
**ブロブから合言葉は割り出せない**（PBKDF2 15万回＋AES-GCM）。会員ページと同じ仕組み。

## 付記: このブランチの `events/` はスナップショット

`events/` の**正は rfwmo8**。このブランチにも同期したコピーをコミットしてあるが、
これは「ビルドがそのまま通る状態にしておくため」のスナップショットで、時間が経てば古くなる。
組み立てる前に上の同期コマンドを走らせるのが正しい手順。
