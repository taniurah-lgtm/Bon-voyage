## 🔴 売り始める前に（オーナー）

1. **あすぴあに確かめる**（`docs/revenue-ideas.md` §4 の3つ。11/4以降、小川パレットへの棚の相談のついでに）。
   とくに「②ニコマルが事業者向けの原稿を通信とは別に売ることは、登録に響くか」。**答えが出るまで売らない**
2. **見本を目通しして、次の「たたき台」を決める**（Claude が置いた数字。変えたら `scripts/make-b2b.mjs` の申込書を直す）
   - 名前なし（通信の名前とQRを入れない）＝ **＋2,000円/月**
   - 物件シートは **月5件まで**
   - **3か月から**、そのあとは1か月ごと／やめるときは **前の月の10日まで**に連絡
   - お届けは **毎月20日ごろ**に翌月分。物件シートは住所をもらってから **3営業日ほど**
3. **問い合わせ先のメール**: いまは通信と同じ（tokyo.papa.home@gmail.com）。ニコマルのメールにするか決める
4. 本番では、お客さまごとに**配布先コードのQR**を作る（どこから読者が増えたか分かる。`scripts/build-qr.py` と `scripts/build-flyer-landings.mjs` の両方に足す）。見本はホームページのQR

## 毎月の作り方（Claude）

1. 翌月の催しを台帳から選ぶ → `specs/<月>.json`
   - `items`: A4に載せる8件（日付順に並ぶ）。日時・場所・料金は**台帳から写す**。ひとことは**台帳の事実だけ**で書く（盛らない）
   - `line`: お店のLINE用に、items から5件
   - `near`: 物件シートの「近くで開かれる催し」
   - `checked`: 公式を確かめた日（紙に「〇年〇月〇日時点」と出る）
2. `node scripts/make-b2b.mjs <月>` → `sample/` に PDF・HTML・テキスト（物件ごとに作るときは `point` を物件の住所にする。座標は国土地理院の住所検索）
3. 目通し（オーナー）→ メールで送る（PDF＋テキスト）

## 守ること（スクリプトが止めるものは ⛔）

- ⛔ **公式に公開された催しだけ**（公開データにあり、公式URLがあり、日程が仮でないもの）
- ⛔ **主催者の許しが「通信への掲載」までの催しは入れない**（お店の配る紙に広げない）。スクリプトの `PERMISSION_ONLY`:
  E118 玉川上水クリーンフェス（主催者の許し）／E119 Plants Plan Cafe（許し・事前連絡の約束）／E126 こもれびと水車のマルシェ（主催・協力団体とのやりとり）／
  E130 こぐま広場はなこ／E142 オーガニックフェスタ（主催者とのやりとり）／E187 たけのこ公園まつり（自治会からチラシを直接もらった）。
  **新しく主催者とやりとりして載せた催しが出たら、ここに足す**
- ⛔ **協賛（PR）の催しは入れない**（号の web の item に `"pr"` があるもの）
- ⛔ **作り方を書かない**（台帳・巡回・道具・ファイル名）。⛔ **評価の言葉を書かない**（「子育てしやすい」「住みやすい」「閑静」「便利」など＝不動産の表示のきまり）
- 距離は**直線距離の目安**と方角だけ。道のり・歩いてかかる時間は書かない（不動産の表示では「道路距離80mで1分」の決まりがあり、こちらでは測らない）
- 施設は `data/b2b-places.json` に、**市・都の公式で住所を確かめたものだけ**置く。座標は国土地理院の住所検索（住所の代表点）
- **お店のLINE用の文に、通信の宣伝（友だち追加のお願い・URL）は入れない。**出典として名前だけ。
  お店のLINE公式アカウントにとっても「第三者のサービスの宣伝」になりうる（LINE公式アカウント利用規約 第18条(6)・`docs/revenue-ideas.md` §0）
- 料金は**固定額だけ**。成約ごとの報酬は取らない（宅建業法）。お客さまの個人の情報は受け取らない
- 同じ駅の周りに応援型の不動産がいれば、先にそこへ声をかける（同じお店の予算を取り合わない）
