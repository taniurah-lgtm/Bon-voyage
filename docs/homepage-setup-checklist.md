# 公開までに、オーナーが手でやること

カレンダー・地図・投稿フォームのコードは入っている。あとは下の3つ。
①②は Claude 側からは実行できない（合言葉を持っているのはオーナーだけ、
Apps Script はオーナーの Google アカウントで動かす必要がある）。
⓪は「どのブランチを公開するか」の判断なので、指示があれば Claude 側でもできる。

## ⓪ いまの改修は、まだ公開ブランチに乗っていない（最初に決めること）

デプロイの workflow（`.github/workflows/deploy-homepage.yml`）は
**`claude/line-message-resend-yefv9l` に push されたときだけ**動き、
公開するのは `docs/homepage/` だけ。

いまカレンダー・地図・投稿・会員ページの改修が入っているのは
**`claude/handoff-docs-review-wn6glj`**。つまり:

- ①②を済ませても、**このブランチのままでは何も公開されない**。
- 公開するには、wn6glj の内容を yefv9l に取り込んで push する必要がある。

> Claude はこの会話で `wn6glj` にしか push していない（指示された push 先がそこだけのため）。
> yefv9l へ入れてよいと決めたら、その旨を指示すること。

公開前に必ず: `MEMBER_PASS=本物の合言葉 ./scripts/build-site.sh` を通し、
`🔴 検証用の合言葉で組まれたページが残っている` が出ないことを確認する
（出たままだと workflow が止めるので、事故にはならない）。

## ① 合言葉を GitHub の Secrets に入れる（3分・1回だけ）

会員ページと投稿フォームの「サポーター判定」は、ビルド時の合言葉で暗号文を作っている。
**Secrets に入れておけば、公開のたびに手でビルドし直す必要がなくなる。**

1. https://github.com/taniurah-lgtm/Bon-voyage/settings/secrets/actions
2. **New repository secret**
3. Name: `MEMBER_PASS`　Secret: **いま会員に配っている合言葉**
4. Add secret

これで `docs/homepage/**` に push されたとき、デプロイの workflow が
**本物の合言葉でページを組み直してから**公開する。

> 内輪用の別の合言葉（`INSIDER_PASS`）を使っているなら、同じ手順でもう1本足す。
> 両方あれば、どちらの合言葉でも会員ページが開く。

### なぜ必要か（入れないとどうなるか）

リポジトリにコミットされている `m/s7f2ka/index.html` と `map.html` は、
**動作確認のため `testpass` で組まれている**。そのまま公開すると、
本物の合言葉が効かず、`testpass` を知っている人だけが開ける状態になる。

これを防ぐため、検証用の合言葉で組まれたページには
`<!-- BV_BUILD: TEST_PASSPHRASE -->` という印が入るようにした。
**印が付いたままだとデプロイは失敗して止まる**（公開されない）。

つまり `MEMBER_PASS` を入れるまでサイトは更新されない。
逆に言えば、**入れ忘れて事故になることはない。**

## ② 投稿の受け口をデプロイして URL を登録する（10分・1回だけ）

投稿フォームはもうページの中にある。**送り先だけが空**。
未設定でもフォームは表示され、送信すると「まだ設定されていません」と出て、
書いた文章はコピーできる状態で残る（下書きも端末に残る）。書いたものは失われない。

### 手順

1. https://script.google.com/ →「**新しいプロジェクト**」
2. `scripts/gas/map-post-endpoint.gs` の中身を**ぜんぶ**貼り付けて保存
3. 関数の選択で **`setup`** を選んで「実行」
   - 初回だけ Google の認可画面が出る → 許可する
   - 実行ログに**スプレッドシートのURL**と**写真の置き場**が出る。控えておく
4. 右上「**デプロイ**」→「**新しいデプロイ**」→ 歯車から「**ウェブアプリ**」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員** ← ここが「全員」でないと投稿が届かない
5. 出てきた「ウェブアプリのURL」（`https://script.google.com/macros/s/.../exec`）をコピー
6. https://github.com/taniurah-lgtm/Bon-voyage/settings/variables/actions
   → **New repository variable**
   → Name: `MAP_POST_URL`　Value: コピーしたURL

> **Secrets ではなく Variables** に入れる。このURLは公開ページのJSに載るので秘密ではない。
> 秘密にする意味がないものを Secrets に入れると、あとで中身を確認できなくて困る。

### 動いているかの確かめ方

ブラウザでウェブアプリのURLをそのまま開く。`{"ok":true,"service":"bonvoyage-map-post"}`
と出れば生きている。

そのあとサイトの `/map.html#post` から1件テスト投稿して、
スプレッドシートの `投稿` シートに行が増えるのを見る。
**`承認` 列に ✓ を入れるまで地図には出ない**（ここは従来どおり）。

### コードを直したときの注意

Apps Script は**保存しただけでは公開中の中身が変わらない**。
「デプロイの管理」→ 鉛筆マーク →「**新しいバージョン**」→ デプロイ、が必要。
