## 4. 手順（本命ルート）

### 4-1. 事前に谷裏さんから受け取るもの

**会員ページの合言葉**（ひらがなの文字列）。
これは**リポジトリに存在しない**し、してはいけない。谷裏さんに口頭／チャットで聞くこと。

> 用途: 公開用シートで「投稿者がサポーターかどうか」を判定するためだけに使う。
> 判定の**結果**（サポーター／一般）だけが公開され、**合言葉そのものは公開されない**。

### 4-2. スクリプト本体を取得

このリポジトリの `scripts/gas/create-map-form.gs` を読む。**中身を書き換えるのは2箇所だけ。**

```js
const MEMBER_PASS = '';   // ← 4-1 で受け取った合言葉を入れる
const FORM_ID = '1wXA...' // ← 空文字 '' にする（重要）
```

- **`FORM_ID` は必ず `''` にすること。**
  今入っているIDは `h.taniura.0131.nj@gmail.com` の持ち物なので、
  `tokyo.papa.home@gmail.com` から開こうとすると権限エラーで落ちる。
  空にすると、**実行したアカウントの持ち物として新しいフォームを作る**。

### 4-3. ブラウザ操作

1. Chrome を、**`tokyo.papa.home@gmail.com` でログイン済みのプロファイル**で起動する。
   - 既存プロファイルを使うのが確実（新規プロファイルだとログインから必要になる）。
   - **ログインが必要になった場合、パスワードを自分で入力しようとしないこと。**
     画面を谷裏さんに見せて、人にログインしてもらってから続行する。
     （Googleは自動化されたログインを検知して弾く。無理に通そうとしない）
2. https://script.google.com/ を開く →「**新しいプロジェクト**」
3. エディタの既定コード（`function myFunction() {}`）を**全消し**して、4-2で編集したコードを貼る
4. 「プロジェクトを保存」（フロッピーアイコン / Ctrl+S）
5. 上部の関数選択で **`createMapForm`** を選ぶ →「**実行**」

### 4-4. 認可画面の通り方（ここでつまずきやすい）

初回実行時に承認フローが出る。**個人プロジェクトなので「未確認のアプリ」警告が出るのが正常。**

1. 「承認が必要です」→ **権限を確認**
2. アカウント選択 → **`tokyo.papa.home@gmail.com`** を選ぶ（★別アカウントを選ばないこと）
3. 「このアプリは Google で確認されていません」→ 左下の「**詳細**」
4. 「**（安全ではないページ）に移動**」
5. 権限一覧（スプレッドシート・フォーム・Driveへのアクセス）→ **許可**

その後、自動で実行が始まる。

### 4-5. 実行ログを回収

実行完了後、下部の「**実行ログ**」に以下が出る。**全部控えること。**

```
フォーム（配布用URL）: https://docs.google.com/forms/d/e/.../viewform
フォーム（編集用URL）: https://docs.google.com/forms/d/.../edit
スプレッドシート:      https://docs.google.com/spreadsheets/d/.../edit
回答シート名: フォームの回答 1 / 承認列: H
```

> ログに「ファイルアップロード設問は作成できませんでした」と出ることがある。
> **これは想定内で、失敗ではない。**その場合は写真の設問の代わりに
> 「写真は tokyo.papa.home@gmail.com へ」という案内が入る。**そのまま進めてよい。**

### 4-6. 公開用シートをCSVで公開（手作業・自動化不可）

1. 実行ログのスプレッドシートURLを開く
2. **ファイル → 共有 → ウェブに公開**
3. 「リンク」タブ → 対象を **`公開用`** シート、形式を **カンマ区切り(.csv)** に
4. 「公開」→ 確認 → **出てきたURLを控える**

> ⚠️ **必ず「公開用」シートだけを選ぶこと。**
> 「ドキュメント全体」を選ぶと、回答シートに平文で入っている**合言葉が公開されてしまう**。
> ここは事故ると取り返しがつかないので、公開後に必ずURLを開いて中身を目視確認する。
> CSVの列が `タイムスタンプ, 場所, ひとこと, ニックネーム, エリア・年齢, 区分` の6つだけなら正しい。

## 6. 完了後にやること（余力があれば）

`gh` CLI や GitHub連携が使えるなら、続けて以下まで。使えなければ**値の報告だけでよい**。

1. リポジトリ `taniurah-lgtm/Bon-voyage` に登録
   - **Secrets** → `MAP_SHEET_CSV` = 4-6のCSV URL

2. ブランチ `claude/line-message-resend-yefv9l` で
   ```bash

   git add docs/homepage/map.html
   git commit -m "マップに投稿フォームへの導線を追加"
   git push -u origin claude/line-message-resend-yefv9l
   ```
   → マップページに「この地図に書き込む」ボタンが出るようになる。
3. **PRは作らないこと**（このリポジトリの方針）。

## 7. 絶対に守ること

- ❌ **合言葉をリポジトリにコミットしない。** `create-map-form.gs` は `MEMBER_PASS = ''` のまま維持する。
  作業用に書き換えたコードは、リポジトリ外（クリップボード等）で扱う。
- ❌ **回答スプレッドシートを共有・公開しない。** 公開するのは `公開用` シートのCSVだけ。
- ❌ **谷裏さんのパスワードを入力・保存しない。** ログインが要るなら人にやってもらう。
- ❌ **PRを作らない。** push先は `claude/line-message-resend-yefv9l` のみ。
- ⚠️ **`createMapForm` を2回以上実行しない。**
  設問は作り直されるので壊れないが、**スプレッドシートは実行のたびに新しく作られる**。
  投稿が入り始めたあとに再実行すると、参照先がずれる。

## 9. 参考（この先の流れ・作業対象外）

報告された値をもとに、元のセッションが `scripts/map-ingest.mjs` と毎日の巡回を作る。
投稿は「フォーム → シート → 谷裏さんが承認列に✓ → 翌日の取り込みでマップに反映」という流れになる。
