## 最大の関門 — 有料だけに届ける経路

現状: LINE公式アカウントは1つ、`scripts/line_report.sh` は `/broadcast`(=全友だち送信)。無料も有料も同じ友だちリスト。しかも課金は **note(別ID)** なので、**note課金者 ↔ LINE ユーザーの紐付けが無い**。だから「有料の人にだけ週2」を今の仕組みでは自動配信できない。

### 選択肢
- **A. パイロット手動(推奨・すぐ開始可)** … 有料の人には土曜レポートを個別に手渡し(LINEの1:1トーク or メール)。人数が一桁のうちはこれで十分。実装ゼロ・原価ゼロ。
- **B. note メンバー限定記事** … 有料版レポートを note の会員限定投稿として出す。課金者管理は note が担うので **LINE紐付け不要**・堅い。プッシュ感は弱いが運用が軽い。
- **C. LINE narrowcast ＋ タグ** … 課金者にタグ付けして絞り込み配信。要 Messaging API 実装＋課金者特定(申込時に合言葉/LINE表示名申告)。人数が増えてから。
- **D. メール配信** … 申込時にメール取得→週2メール。将来の選択肢。

**推奨路線: 当面 A(手動)で開始 → 人数が増えたら B(note限定) か C(narrowcast) へ格上げ。**

## カレンダー登録代行 — 具体設計

1. **依頼の受け方**: 「E3を登録」の返信を受ける経路が要る。当面は有料の人と **LINE 1:1 or メール**で直接やりとりし、その指示をこのリポジトリの Claude に渡して Google Calendar MCP で登録する。
2. **相手のカレンダーへの入れ方(3案)**:
   - **共有カレンダー購読(推奨)** … 「ぼんぼやーじゅ・おすすめ」カレンダーを1つ作り、有料の人に購読URLを渡す。登録は全部そこへ。一番軽い。
   - ゲスト招待 … イベント作成時に相手の Gmail をゲスト追加→相手が承諾で相手のカレンダーに出る。個別最適が要る人向け。
   - .ics 送付 … 個別イベントを .ics で送り取り込んでもらう。
3. **前日リマインダー**: イベント側の reminder(前日18:00 popup)で対応。`CLAUDE.md` の既定どおり。
4. **必要情報**: 相手の Gmail(招待/共有用)。申込フォームで取得する。
