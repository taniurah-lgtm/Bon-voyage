# Threads API の申請手順（`threads_keyword_search` を通すまで）

**目的**: Threads の公開投稿をキーワードで検索し、**読者になりそうな人**を毎朝まとめて受け取る。
（イベント探しが目的ではない。理由は `docs/social-automation.md` §6）

**調査日**: 2026-09-13。Meta は仕様をよく変えるので、**画面と違ったら画面を正とする。**

---

## 0. 🔴 先に知っておくこと（ここを読まずに始めると、順番を間違える）

### ① レート制限は、思っていたより緩い（**前の記述を訂正する**）

公式ドキュメント（`developers.facebook.com/docs/threads/keyword-search/`）の記載は
**「A user can send a maximum of 2,200 queries within a rolling 24-hour period」**。
**結果が0件のクエリはカウントされない。**

⚠️ **これ以前に「500クエリ/7日」と書いていたが、それは二次情報（外部ブログ）だった。公式は上の数字。**
毎朝キーワードを10本回しても **1日10クエリ**。**制限は実質、考えなくてよい。**

### ② 承認が無いと「自分の投稿しか検索できない」

> If your app has not been approved for the `threads_keyword_search` permission,
> the search will be performed only on posts owned by the authenticated user.

**＝審査を通さないと、この機能は何の役にも立たない。**動くには動くので、
「APIは叩けている」と勘違いしやすい。**他人の投稿が返っているかで判定する。**

### ③ 🔴 開業届が要る（いちばん長い道）

Meta のドキュメント:
> Apps that request **advanced access** for permissions ... must be connected to a
> **Business that has completed Business Verification**.

他人の公開投稿を読むのは advanced access にあたる。
→ **ビジネス認証が要る** → **日本の個人事業主の場合、実務上「開業届の控え（受付印つき／e-Taxなら受信通知）」が本命の書類。**

**つまり、`docs/tasks.md` §3 の「開業届＋特商法表記」と、この申請は同じ一本道。**
開業届は **LINE認証済アカウントの再申請**にも効くので、**3つが1つの作業でほどける。**

> ⚠️ **ただし、自分のアプリが本当に advanced access 扱いかは、画面で確かめられる。**
> App Dashboard の権限の行に **Standard / Advanced** と、ビジネス認証が要るかが出る。
> **そこが正。**Standard で済むなら、開業届を待たずに進められる。**手順4の時点で必ず見ること。**

## 1. 全体の順番（この順にしか進めない）

```
① Meta開発者アカウント  →  ② アプリ作成(Threads)  →  ③ 自分をテスターにしてトークン取得
                                                              ↓
                                    ④ 実際に keyword_search を1回以上叩く ★必須
                                                              ↓
    ⑤ ビジネス認証(1〜5営業日) ←── 開業届の控え        ⑥ 提出物をそろえる
                                          ↓                   ↓
                                        ⑦ App Review 提出（審査 約1週間）
                                                              ↓
                                                ⑧ アプリを「公開」に切り替える
```

🔴 **④ を飛ばすと提出できない。**提出前チェックリストに
**「各パーミッションで30日以内にAPI呼び出しを実施済みであること」**が入っている。
**「審査に通ってから使う」ではなく「使ってから審査に出す」。**ここを間違える人が多い。

## 2. ① Meta開発者アカウント（SMSで止まっている件）

Notion の残タスクに「**Meta開発者登録がSMS認証で停止中**」とある。**ここから。**

よくある詰まり方と、報告されている抜け道:

| 症状 | 対処 |
|---|---|
| 「Sorry, a temporary error has occurred」でSMSが送れない | **Facebook側の設定で電話番号をいったん外して、入れ直す。**そちらでSMSが届くのを確認してから、開発者登録に戻る（登録側の確認を飛ばせることがある） |
| クレジットカードでの確認リンクが開かない | **リンク切れが報告されている。**期待しない |
| どちらも駄目 | **Meta Developer Support のフォームから問い合わせる**（`developers.meta.com/horizon/support/`） |

> 💡 **電話番号を変えられるなら、それがいちばん早い。**格安SIMや一部のIP電話番号は、
> Meta側で弾かれることがある。**普段使いの携帯番号で試す。**

## 3. ② アプリを作る

1. `developers.facebook.com` → **マイアプリ** → **アプリを作成**
2. ユースケースで **「Threads API へのアクセス」** を選ぶ
   （他のユースケースを選ぶと Threads の権限が出てこない）
3. 🔴 **アプリIDが2つ発行される。Threads 用は「Threads app ID」のほう。**
   Facebook 側のIDと間違えると、以降ずっと動かない
4. **アプリアイコンを 1024×1024 で設定する**（審査の必須項目。あとで慌てない）
5. **プライバシーポリシーURL** を設定 → `https://bonvoya.nicomaru.tokyo/tokushoho.html`
   （「免責事項・個人情報の取り扱い」ページ。§6 で中身を確認すること）

---

## 4. ③ トークンを取る（開発モードのまま）

1. アプリの **「アプリロール」→ 自分の Threads アカウントを **Threads Tester** として追加
2. Threads アプリ側で**招待を承認する**（Threads の設定 → ウェブサイトの権限 / 招待）
3. 🔴 **自分の Threads プロフィールを「公開」にしておく。**
   非公開だと権限の自動延長が効かない
4. **リダイレクトURIを登録する。**サーバを立てたくないなら `https://localhost/` でよい
   （手で認可コードを拾う用）
5. 権限のスコープに **`threads_basic` と `threads_keyword_search`** を入れて認可 → 短期トークン
6. 短期トークンを**長期トークン（60日）**に交換する

> 📌 **この時点では、他人の投稿は返ってこない。**自分の投稿だけが返る。**それが正常。**

---

## 5. ④ ★必須: 実際に1回叩く（これを飛ばすと提出できない）

```
GET https://graph.threads.net/v1.0/keyword_search
      ?q=小平
      &search_type=TOP
      &search_mode=KEYWORD
      &limit=25
      &access_token=<長期トークン>
```

**成功レスポンスが返れば、それで条件を満たす**（中身が自分の投稿だけでも構わない）。
**提出は、この呼び出しから30日以内に行う。**

回すつもりのキーワード（申請の説明文にもそのまま使える）:
`小平市` / `花小金井` / `小平 子育て` / `小平 おでかけ` / `多摩 子連れ` / `小平 保育園` / `小平 幼稚園`

## 6. ⑥ 提出物（先にそろえると、審査が1回で終わる）

### スクリーンキャスト（いちばん落ちる項目）

| 要件 | 中身 |
|---|---|
| 解像度 | **1080p以上・幅1440px以下** |
| 言語 | **英語のUIで撮る。**無理ならキャプションを付ける |
| 音声 | **なし** |
| カーソル | **マウスの動きが見えるように** |
| 内容 | **申請する権限を1つずつ、実際に使っているところ**を映す |

→ 撮るもの: ログイン → 認可画面で `threads_keyword_search` に同意 →
　`keyword_search` を叩く → **結果が画面に出る** → それを自分が読んでいる、まで。

### 説明文（権限ごとに**個別に**書く。使い回すと落ちる）

4点を必ず含める: **ユーザーへの効果 / 必要な理由 / データの使い道 / なぜ必須か**。

`threads_keyword_search` 用の下書き（このまま英訳して使える）:

> 小平市とその近隣で子育てをしている人の公開投稿を、地域名のキーワードで探すために使います。
> 見つけた投稿には、地域のおでかけ情報（無料の週次ニュースレター）をお知らせする返信を、
> 人が内容を読んだうえで手で書きます。**自動で返信は送りません。**
> 取得したデータは**運営者が読むためだけ**に使い、第三者に渡さず、保存もしません。
> この権限が無いと、検索は自分の投稿しか返さないため、機能そのものが成立しません。

🔴 **「自動返信はしない」と書いたら、本当にしないこと。**書いたとおりに運用する。

### そのほか

- アプリアイコン **1024×1024**
- **プライバシーポリシーURL**（下記を満たしているか確認）
- アプリの用途の分類（**自分自身のため** を選ぶ。クライアント向けではない）
- アプリのカテゴリ

### プライバシーポリシーの中身を確認する

`https://bonvoya.nicomaru.tokyo/tokushoho.html` に、**Threads から取得する情報の扱い**が
書かれているか見る。書かれていなければ **1段落足す**:

> 当サイトの運営者は、Threads の公開投稿を、地域の子育て情報をお届けする目的でのみ閲覧します。
> 取得した情報を第三者に提供することはなく、保存もしません。

**データ削除の窓口**も要る。既に問い合わせ先のメールアドレスがページにあるなら、それで足りる。

## 7. ⑤ ビジネス認証（開業届が要る側）

1. **ビジネスマネージャ**（`business.facebook.com`）でビジネスを作る
2. アプリをそのビジネスに紐づける
3. **ビジネス情報 → 認証**から書類を出す

日本の個人事業主で通っている書類:

| 書類 | 注意 |
|---|---|
| **開業届の控え** | **受付印つき。**e-Tax なら**受信通知（受付番号入り）**も一緒に |
| 確定申告書 第一表の控え | 直近年度。受付印か電子受付番号が要る |
| 屋号入りの公共料金明細 | **屋号名義で届いているもの**に限る |

- **発行から3〜12か月以内**の「最近の書類」を求められる
- **審査は通常 1〜5営業日**
- ⚠️ **ビジネス認証が「審査中」のままだと、App Review の提出自体がブロックされる**という報告がある。
  **だから、先に済ませる**

---

## 8. ⑦⑧ 提出と、そのあと

- 審査の目安は **約1週間**
- 通ったら、アプリを **開発モード → 公開**に切り替える。**ここまでやらないと有効にならない**
- **通ったかの確かめ方**: `keyword_search` を叩いて、**自分以外のアカウントの投稿が返るか。**
  返らなければ、権限が承認されていないか、アプリがまだ開発モード

### 落ちたときは

理由が個別に返ってくる。**多いのはスクリーンキャストと説明文。**
（権限を使っている場面が映っていない／説明が一般論で、この権限でなければならない理由が無い）
**修正して出し直せる。回数の制限は無い。**

## 9. 通ったあとに作るもの（審査が通るまでは作らない）

1. GitHub Actions の cron（毎朝）→ `keyword_search` を数本 →
   **結果を `docs/` か Issue に下書きとして書く**
2. **オーナーが読んで、返信するかを決める。**判断基準と文案は `docs/threads-outreach.md`
3. 🔴 **自動で返信しない**（申請の説明文にそう書くため。書いたとおりに運用する）

> 💡 **トークンは60日で切れる。**更新の仕組み（`refresh_access_token`）を入れておかないと、
> **2か月後に黙って止まる。**9/9 の Routine と同じ壊れ方をする。
> **GitHub Secrets に入れるトークンは、月1で更新するワークフローとセットにする。**

## 10. まとめ: オーナーがやること（この順）

- [ ] **1. 開業届を出す**（税務署／e-Tax。**控え・受信通知を必ず保管**）← 最長・LINE再申請にも効く
- [ ] **2. Meta開発者アカウントのSMSを通す**（§2 の抜け道 → 駄目ならサポート）
- [ ] **3. アプリを作る**（Threads ユースケース。アイコン1024・プライバシーポリシーURL）
- [ ] **4. トークンを取り、`keyword_search` を1回叩く**（★30日以内に提出する）
- [ ] **5. 権限の行が Standard か Advanced かを見る**（Standard なら開業届を待たずに6へ）
- [ ] **6. ビジネス認証**（開業届の控え。1〜5営業日）
- [ ] **7. スクリーンキャストを撮る**（1080p以上・幅1440px以下・音声なし・英語UI）
- [ ] **8. App Review 提出**（審査 約1週間）
- [ ] **9. アプリを公開に切り替え、他人の投稿が返るか確認**

**3〜4 と 7 は Claude 側で手伝える**（叩くコマンド・説明文の英訳・撮る手順の台本）。
