# 担当分け — オーナーは窓口とだけ話す

2026-09-17 決定。会話を1本に絞り、**オーナーは窓口（メインの会話）とだけ話す。**
窓口が必要に応じて専門の担当を呼ぶ。担当の定義は `.claude/agents/*.md`。

## 組織

| 担当 | 呼び名 | 何をする | 何をしない |
|---|---|---|---|
| **窓口** | （この会話） | 話を聞く・判断する・担当に振る・commitとpush | — |
| **裏取り** | `verifier` | 公式ページで日付・料金・対象を1件ずつ確かめ、確度を判定 | 起票・文面 |
| **台帳** | `ledger` | 起票・ID採番・月替わり・終了の反映 | 配信 |
| **広報** | `sns` | 投稿案・返信案・リール構成・SNSで見つけたものの引き渡し | 投稿・返信の送信 |
| **営業** | `sales` | 協賛先のリサーチ・相手ごとの台本・リードの更新 | 電話・メール・訪問 |
| **版下** | `press` | チラシ・ポスター・QR・PDFの検査 | 印刷の発注 |
| **監査** | `audit` | ズレ・矛盾・ルール違反を洗い出す | 修正（報告だけ） |

## 🔴 誰にも渡さない仕事

**この6つは、担当にやらせない。オーナーの承認を経て、窓口が手でやる。**

1. **LINEの送信** — 2026-09-16、64人に3通送った。原因は自動で動くものが草案を見ずに書いたこと
2. **SNSへの投稿・返信の送信** — 読者との会話には人格と責任が要る
3. **先方への連絡**（電話・メール・訪問） — 相手は生身の人
4. **印刷の発注** — 刷り直しは実費
5. **ブランチの削除** — そもそもこの箱からはできない（プロキシが拒む）。オーナーがGitHubの画面で
6. **`reports/free/sent.log` への書き込み** — 送っていない号がホームページに出る

## ご提案の4分割から、2つ変えた理由

### ①「情報解析→裏取り」は、2つの別の仕事

2026-09-15 にオーナー自身が分けた線をそのまま使う。

- **広く浅く探す**（落とさないことが仕事） … 広報担当と、火曜の Gemini
- **公式で裏を取る**（間違えないことが仕事） … 裏取り担当

**同じ担当にやらせると、探しながら「たぶん合ってる」で通してしまう。**
広報担当は「こういうものが出ていた」で止め、裏取りは裏取り担当が受ける。

### ②「総務が水曜配信の送り出しをする」は、送り出しだけ外す

台帳作りと号の組み立てまでは担当でよい。**送信だけは渡さない。**

🔴 2026-09-16 の3通配信が、まさに「自動で動くものが送った」事故だった。
前日に合意した草案があったのに、Routine が別のブランチで自分の版を書いて送り、
**降水確率90%の連休にプールを薦めた。**訂正と補足で計3通になった。

**送る前に人が紙面を読む。**これは例外を作らない。

## 窓口の使い分け（担当を呼ぶ／呼ばない）

**呼ぶのは、扇状に広がる仕事だけ。**担当は毎回ゼロから始まるので、
呼ぶこと自体にコストがある。窓口の中でできることを外に出すと、かえって遅い。

| 呼ぶ | 呼ばない |
|---|---|
| 10件のイベントを並列に裏取り | 1件だけ確かめる |
| 協賛先を30軒洗い出す | 既にあるリードの次の一手を決める |
| 全チラシの版下を作り直す | 1文字直す |
| 大きな作業の前後の監査 | 日常のちょっとした確認 |

## 担当に共通の約束

1. **見ていないことを書かない**
2. **自分のブランチの最大値でIDを振らない。**全ブランチを `git fetch` して最大値+1
3. **commit と push はしない。**窓口がまとめてやる
   （ブランチが分かれた結果、9/16 の事故と E104〜E112 の全面衝突が起きた）
4. **判断に迷ったら、決めずに窓口へ返す**
