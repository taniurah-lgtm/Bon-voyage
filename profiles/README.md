# profiles/ — ユーザープロフィール(チューニングの中心)

無料パイロットの「ウリ」= **一人ひとりに合わせてイベントを出し分ける**ための設定置き場。

## 仕組み(共通調査 → 個別レポート)

コストを抑えるため、調査は1回・レポートは人ごとに出し分ける:

1. **共通調査**: `active: true` の全プロフィールの「対象エリア」と「興味カテゴリ」の**和集合**を1回だけ巡回し、`events/` 台帳を更新する(1エリアに人が増えるほど1人あたりのコストは下がる)。
2. **個別レポート**: プロフィールごとに台帳を絞り込み・並べ替えて `reports/<id>/YYYY-MM-DD.md` を生成する。
3. **配信**: `delivery` に従って届ける(`line`=自動push / `email` / `manual`=オーナーが手渡し)。

## プロフィール様式

`_template.md` をコピーして `profiles/<id>.md` を作る。先頭の YAML ブロックが機械可読な設定、その下は自由メモ。

### カテゴリ語彙(categories)
| タグ | 意味 |
|---|---|
| `summer_festival` | 夏祭り・盆踊り・縁日 |
| `fireworks` | 花火大会 |
| `pool_water` | プール・水遊び・じゃぶじゃぶ池 |
| `camp` | キャンプ・アウトドア |
| `zoo_aquarium` | 動物園・水族館・牧場 |
| `indoor_play` | 屋内遊び場・雨の日スポット |
| `harvest` | 味覚狩り・農業体験(いちご/ぶどう/芋 等) |
| `autumn_leaves` | 紅葉・自然 |
| `illumination` | イルミネーション・クリスマス |
| `museum_science` | 博物館・科学館・プラネタリウム |
| `seasonal_event` | 季節の行事・マルシェ・地域フェス |
| `sports_watch` | スポーツ観戦 |

季節でカテゴリの旬が変わる(夏=祭り/花火/プール、秋=紅葉/味覚狩り、冬=イルミ/屋内)。巡回はその時季に合うカテゴリを厚めに調べる。

### 対象エリア(coverage)
| 値 | 範囲の目安 |
|---|---|
| `neighborhood` | 徒歩・自転車圏(最寄駅周辺) |
| `city` | 市区内 |
| `tama` | 多摩地域全体 |
| `tama_plus_tokyo` | 多摩＋都心も |
| `kanto_drive` | 車での遠出(キャンプ等。`camp_drive_hours` で圏を指定) |

## 運用メモ
- `active: false` のプロフィールは調査・配信の対象外(休止)。
- 個人情報(連絡先・子の年齢)を含むため、**このリポジトリを公開しない**。LINEトークン同様、機微情報の扱いに注意。
- 新しい人が遠方エリアだと新規調査が増える。まずは多摩・中央線沿線で密度を作る。
